## 문제 상황

LLM 에이전트는 웹페이지, 메일, 문서를 읽다가 그 안에 숨은 지시("이전 지시를 무시하고 ...")를 따를 수 있습니다. 이것을 **간접 프롬프트 인젝션**이라고 합니다.
문서마다 큰 LLM으로 검사하면 느리고 비쌉니다. 판정 전용 모델 **Jev**를 앞단 필터로 두면 싸고 빠릅니다.
**그런데 이 필터를 얼마나 믿을 수 있는지는 아직 아무도 재 보지 않았습니다.** 이 프로젝트는 그것을 측정합니다.

### 선행 연구 표 (우리가 확인하려는 약점)

| 축 | 알려진 결과 | 우리 실험 |
| --- | --- | --- |
| 길이 | 512토큰 탐지기 recall: 잘리지 않은 공격 34%, 잘린 공격 11% | ①-b |
| 위치 | 중간·끝에 삽입하면 공격 성공률이 높음 (0.53→0.87) | ① 위치별 |
| 오탐 | 트리거 단어가 있는 정상 입력에서 정확도 약 60% | ① 과탐지 참고 세트 |
| 말투 | 한국어 협박체 정상 문장 오탐률 55~98% | ② |
| 적응형 공격 | 점수 피드백 탐색으로 공격 성공률 90% 이상 | ③ (c) |
| Jev 자체 | "스스로 분류를 주장하는 텍스트"와 긴 State가 약점이라고 공식 문서가 인정 | ③ (a), ①-b |

**우리가 채우는 빈틈 3가지**
1. Jev를 인젝션 가드로 평가한 결과가 없습니다.
2. "이 문서는 검토를 통과했다"처럼 판정기를 설득하는 문구를 다룬 논문이 없습니다.
3. 한국어 인젝션을 "번역한 뒤 판정"하는 방법의 효과를 잰 연구가 없습니다.

### 평가 지표 (모든 단계 공통)

| 지표 | 뜻 | 좋은 방향 |
| --- | --- | --- |
| TPR | 인젝션을 인젝션으로 잡은 비율 | 높을수록 좋음 |
| FPR | 정상 문서를 인젝션으로 잘못 잡은 비율 | 낮을수록 좋음 |
| AUC | 임계값과 관계없이 두 집단을 얼마나 잘 가르는가 | 1에 가까울수록 좋음 |

- 임계값은 0.5입니다. 반드시 `src/jev_guard.py`의 `judge()`와 `metrics()`만 사용합니다. 그래야 두 사람의 결과를 서로 비교할 수 있습니다.
- 비교 기준선: 길이만으로 라벨을 맞히는 AUC는 EN 0.548, KO 0.564, JA 0.546입니다. Jev의 AUC가 이 값보다 충분히 높아야 내용을 보고 판정한다고 말할 수 있습니다.

| H4 | 발표일 11/17 확인 |
| H5 | Enron(AESLC) 라이선스 "unknown" 처리 결정 (공개 레포) |

시간이 부족하면 D5와 F4의 탐색 횟수를 먼저 줄입니다. C와 G1은 채점의 "기능 구현"과 직결되므로 줄이지 않습니다.

## 협업 규칙

- **작업을 시작하기 전에** 이 문서의 "현재 상태와 담당" 표에서 담당을 확인하고, 비어 있으면 자기 이름을 적어 먼저 알립니다. 같은 일을 두 번 하지 않기 위해서입니다.
- **실험 결과 형식**: `results/<실험이름>/`에 질문별 샘플 결과 `<질문>_predictions.csv`(`uid`, `label`, `p`, `latency_s`)와 `summary.json`(TPR, FPR, AUC, n, 모델 버전, 날짜, 커밋 해시, 소요 시간, 오류·재시도 수)을 남깁니다. 보고서의 판정 사례, 기준선 대비 Δ, 한국어 짝 비교에 샘플별 p가 필요합니다. 자세한 규칙은 루트 `CLAUDE.md`.
- 단계마다 `feat/<단계>` 브랜치 → PR → 상대방 리뷰 → merge. `src/jev_guard.py`를 고치는 PR은 반드시 상대방이 리뷰합니다.
- API 키는 코드, 노트북 출력, 커밋, 채팅 어디에도 넣지 않습니다.
- 결정이 나면 `docs/PROJECT.md`의 결정 기록 표에 한 줄 추가합니다.
- API 호출 결과는 csv로 캐시해서 같은 호출을 반복하지 않습니다.
- 데이터셋 파일을 바꾸면 `data/injection_eval/README.md`의 개수와 구성도 함께 고칩니다.
